# API reference

Base URL: `http://localhost:8000`. All business endpoints are under
`/api/v1`. Interactive OpenAPI/Swagger docs are auto-generated by FastAPI at
`/docs` and `/redoc` while the server is running.

## Health

### `GET /health`
Returns overall status, active provider names, and knowledge-base counts.
Used by the System Status page and Docker healthchecks.

```json
{
  "status": "ok",
  "database": "ok",
  "llm_provider": "mock-deterministic",
  "embedding_provider": "hashing",
  "knowledge_base": { "sources": 12, "graph_nodes": 23, "graph_edges": 22 }
}
```

## Conversations

- `POST /api/v1/conversations` `{ "title"?: string, "session_id"?: string }` → `ConversationOut`
- `GET /api/v1/conversations` → `ConversationOut[]`
- `GET /api/v1/conversations/{id}` → `ConversationOut`
- `GET /api/v1/conversations/{id}/messages` → `MessageOut[]`
- `POST /api/v1/conversations/{id}/messages`
  `{ "content": string, "structured_input"?: object }` →
  `ConversationTurnResponse` (assistant message, clarifying questions,
  profile completeness, extracted fields, conflicts, `ready_for_assessment`).

Example:

```bash
curl -X POST localhost:8000/api/v1/conversations -d '{"title":"demo"}' -H 'Content-Type: application/json'
curl -X POST localhost:8000/api/v1/conversations/<id>/messages \
  -H 'Content-Type: application/json' \
  -d '{"content":"Semi-arid region, monoculture wheat, low rainfall, soil organic carbon 0.3%."}'
```

## Profiles

- `POST /api/v1/profiles` → `EnvironmentalProfileOut`
- `GET /api/v1/profiles/{id}` → `EnvironmentalProfileOut`
- `PATCH /api/v1/profiles/{id}` (partial update) → `EnvironmentalProfileOut`
- `POST /api/v1/profiles/{id}/observations`
  `{ "metric": string, "value": number, "unit"?, "source"?, "confidence"?, "notes"? }` → `ObservationOut`
- `GET /api/v1/profiles/{id}/observations` → `ObservationOut[]`

## Assessments

- `POST /api/v1/assessments` `{ "profile_id": string, "conversation_id"?: string }` → `AssessmentOut`
- `GET /api/v1/assessments/{id}` → `AssessmentOut`
- `POST /api/v1/assessments/{id}/reassess` → `AssessmentOut` (new version, includes `diff_from_previous`)
- `GET /api/v1/assessments/{id}/export` → same payload as a downloadable JSON file

`AssessmentOut` shape (abbreviated — see `app/schemas/assessment.py` for the full contract):

```json
{
  "id": "...", "version": 1,
  "assessment_summary": "...",
  "known_facts": [{"field": "soil_organic_carbon", "value": 0.3, "unit": "%", "source": "user_provided"}],
  "unknowns": ["soil_ph", "soil_moisture"],
  "variables_considered": ["soil_organic_carbon", "rainfall", "land_use_type", "biodiversity_indicators"],
  "reasoning_paths": [{"variables": [...], "steps": [...], "narrative": "..."}],
  "recommendations": [{
    "title": "...", "what_to_do": "...", "why_it_may_work": "...",
    "impacted_metrics": ["..."], "time_horizon": "medium",
    "feasibility_constraints": ["..."], "trade_offs": ["..."],
    "confidence": {"level": "low", "reason": "..."},
    "evidence": [{"claim": "...", "claim_type": "source_supported", "citation": "https://doi.org/...", "evidence_status": "supported", ...}],
    "monitoring_plan": [{"metric": "...", "measurement_method": "...", "target": "Establish a baseline first; ..."}],
    "heuristic_score": {"label": "prototype_decision_support_heuristic", "total": 0.66, ...}
  }],
  "overall_limitations": ["..."]
}
```

If fewer than 3 variables are known, `recommendations` is `[]` and
`overall_limitations` states this explicitly (see reasoning-methodology.md).

## Knowledge

- `POST /api/v1/knowledge/ingest` — add a source (text/abstract + metadata);
  chunks + embeds it; returns `{source_id, chunk_count, warnings[]}`.
- `GET /api/v1/knowledge/sources` / `GET /api/v1/knowledge/sources/{id}`
- `GET /api/v1/knowledge/graph` → `{nodes: [...], edges: [...]}`
- `POST /api/v1/retrieval/inspect` `{ "query": string, "profile_id"?: string, "top_k"?: number }`
  → full retrieval trace (expanded terms, graph concepts, semantic/lexical
  candidate counts, ranked results with match reasons).

## Recommendations

- `GET /api/v1/recommendations/{id}`
- `GET /api/v1/recommendations/{id}/evidence` → `EvidenceRef[]`
- `GET /api/v1/recommendations/{id}/monitoring` → `MonitoringPlanItem[]`

## Error handling

All 4xx/5xx responses are `{"detail": "..."}`. Unhandled exceptions are
caught by a global handler (`app/main.py`) and return a generic 500 without
leaking stack traces; details are logged server-side only.
